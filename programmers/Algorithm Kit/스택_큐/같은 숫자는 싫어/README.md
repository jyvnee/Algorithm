# 같은 숫자는 싫어

## 사용 알고리즘

- 스택
- 배열
- 투 포인터

## 풀이 기록

### v1

#### 풀이 아이디어

배열 `arr`를 처음부터 끝까지 한 번 순회하면서, 직전에 저장한 숫자(`current`)와 현재 숫자를 비교한다.

1. `arr[0]`을 결과 리스트에 넣고 `current`로 설정한다.
2. `i = 1`부터 끝까지 순회하며 `arr[i]`가 `current`와 같으면 건너뛴다.
3. 다르면 `current`를 `arr[i]`로 갱신하고 결과 리스트에 추가한다.
4. 순회가 끝나면 결과 리스트를 `int[]` 배열로 변환해 반환한다.

리스트를 스택처럼 사용해, 직전에 쌓인 값과 다음 값을 비교하며 연속된 중복만 제거하는 방식이다.

#### 시간복잡도

```text
O(N)
```

배열 `arr`의 길이 `N`만큼 한 번만 순회한다.

#### 공간복잡도

```text
O(N)
```

최악의 경우(모든 원소가 서로 달라 하나도 제거되지 않는 경우) 결과를 담는 `List<Integer>`와 최종 `answer` 배열이 각각 입력 크기만큼의 공간을 차지한다.

#### 개선 가능한 부분

- `List<Integer>`는 `int`를 `Integer`로 오토박싱해서 저장하므로, 배열 크기가 최대 1,000,000까지 커질 수 있는 이 문제에서는 오버헤드가 발생한다. 결과를 담을 `int[]` 배열을 입력과 같은 크기로 미리 만들고, 쓰기 위치를 가리키는 인덱스(투 포인터)를 두어 값을 바로 덮어쓰면 박싱 비용과 리스트→배열 변환 과정을 없앨 수 있다.
- `list.get(i)`를 사용하는 마지막 변환 루프는 `ArrayList` 기준으로는 O(1) 접근이지만, 리스트 자체를 없애면 이 루프도 함께 제거된다.

### v2

#### 풀이 아이디어

`List<Integer>` 같은 별도의 자료구조 없이, 입력 배열 `arr` 자체를 인플레이스로 압축한다.

- 읽기 포인터 `i`로 배열을 처음부터 끝까지 순회한다.
- 쓰기 포인터 `writeIndex`는 압축된 결과를 채워 넣을 위치를 가리킨다.
- `arr[writeIndex - 1]`(직전에 써 넣은 값)과 `arr[i]`가 다를 때만 `arr[writeIndex]`에 `arr[i]`를 쓰고 `writeIndex`를 1 증가시킨다.
- 순회가 끝나면 `arr`의 앞부분 `[0, writeIndex)` 구간에 압축된 결과가 남는다.

v1에서는 `List<Integer>`에 값을 담았다가 마지막에 `int[]`로 변환했지만, v2는 리스트를 전혀 사용하지 않고 입력 배열을 직접 덮어써서 압축한다.

#### 알고리즘 풀이

`writeIndex`는 "지금까지 압축된 결과의 개수"이자 "다음에 값을 써야 할 위치"를 동시에 의미한다. 따라서 `arr[writeIndex - 1]`은 항상 압축된 결과의 마지막 원소, 즉 직전 숫자를 가리킨다.

```java
int writeIndex = 0;

for (int i = 0; i < arr.length; i++) {
    if (writeIndex == 0 || arr[writeIndex - 1] != arr[i]) {
        arr[writeIndex++] = arr[i];
    }
}
```

`writeIndex == 0`은 아직 아무 값도 쓰지 않은 첫 원소를 처리하기 위한 조건이다. 첫 원소는 비교할 직전 값이 없으므로 무조건 써야 한다.

읽기 포인터 `i`가 항상 쓰기 포인터 `writeIndex`보다 크거나 같으므로, `arr[i]`를 읽은 뒤 `arr[writeIndex]`에 써도 아직 읽지 않은 값을 덮어쓸 위험이 없다.

순회가 끝나면 `arr[0]`부터 `arr[writeIndex - 1]`까지가 압축된 결과이므로, `Arrays.copyOf(arr, writeIndex)`로 정확한 크기의 배열만 새로 만들어 반환한다.

#### 시간복잡도

```text
O(N)
```

배열 `arr`의 길이 `N`만큼 한 번만 순회하며, `Arrays.copyOf`도 결과 크기만큼 한 번 복사한다.

```text
O(N) + O(N)
→ O(N)
```

#### 공간복잡도

```text
O(N)
```

압축 자체는 입력 배열을 그대로 재사용하므로 추가 공간이 `O(1)`이지만, 반환값은 입력과 별개의 배열이어야 하므로 `Arrays.copyOf`가 만드는 결과 배열만큼 `O(N)`의 공간이 필요하다.

#### 개선 가능한 부분

- 현재 풀이는 압축 과정 자체는 `O(1)`의 추가 공간만 사용하며, 반환 타입이 `int[]`인 이상 결과를 담을 `O(N)` 공간은 피할 수 없다. 시간복잡도와 공간복잡도 모두 이 문제에서 더 개선하기 어렵다.
- `writeIndex == 0` 조건을 매 반복마다 검사하는 대신, 반복문 진입 전에 `arr[0]`을 미리 써 넣고 `writeIndex`를 1, `i`를 1부터 시작하면 첫 원소에 대한 분기를 없앨 수 있다.
