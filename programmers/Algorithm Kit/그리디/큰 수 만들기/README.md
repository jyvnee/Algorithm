# 큰 수 만들기

## 알고리즘 분류

- 그리디
- 스택
- 문자열

## 문제 정의

숫자 문자열 `number`의 상대적인 순서를 유지하면서 정확히 `k`개의 숫자를 제거해, 만들 수 있는 가장 큰 숫자를 문자열로 반환한다.

크기가 같은 숫자는 앞자리가 클수록 더 크므로, 각 위치에서 가능한 큰 숫자가 앞에 남도록 선택해야 한다.

## 풀이 기록

### v1

#### 풀이 아이디어

데크를 스택처럼 사용하여 아직 제거되지 않은 숫자를 순서대로 저장한다.

새로 읽은 숫자가 데크의 마지막 숫자보다 크면, 마지막 숫자를 제거하는 것이 더 큰 앞자리를 만든다. 따라서 삭제 횟수가 남아 있고 새 숫자가 더 큰 동안 데크의 뒤에서 숫자를 계속 제거한다.

모든 숫자를 확인한 뒤에도 삭제 횟수가 남았다면, 현재 데크의 숫자는 뒤로 갈수록 커지지 않는 형태이다. 이때는 자릿값이 가장 작은 뒤쪽 숫자를 남은 횟수만큼 제거한다.

#### 자료구조 선택

`ArrayDeque<Character>`를 사용한다.

- 마지막 숫자와 현재 숫자를 비교할 수 있다.
- 뒤쪽 숫자를 `O(1)`에 제거할 수 있다.
- 모든 선택이 끝난 뒤 앞에서부터 꺼내어 결과 문자열을 만들 수 있다.

#### 알고리즘 풀이

##### 1. 삭제 가능 횟수와 데크 초기화

`remaining`에 아직 삭제해야 할 숫자의 개수를 저장하고, 첫 번째 숫자를 데크에 넣는다.

```java
int remaining = k;

Deque<Character> dq = new ArrayDeque<>();
dq.offer(number.charAt(0));
```

##### 2. 더 큰 숫자 앞의 작은 숫자 제거

두 번째 숫자부터 차례로 확인한다. 현재 숫자가 데크의 마지막 숫자보다 크면, 삭제 횟수가 남아 있는 동안 마지막 숫자를 제거한다.

```java
while (remaining > 0
        && !dq.isEmpty()
        && dq.peekLast() < number.charAt(i)) {
    dq.pollLast();
    remaining--;
}
```

예를 들어 `number = "1924"`, `k = 2`인 경우의 선택 과정은 다음과 같다.

```text
1 저장                 -> [1]
9 확인, 1 제거       -> [9], remaining = 1
2 저장                 -> [9, 2]
4 확인, 2 제거       -> [9, 4], remaining = 0

결과: 94
```

현재 숫자보다 작은 숫자가 여러 개 연속하는 경우도 `while`문으로 한 번에 제거한다.

##### 3. 현재 숫자 저장

제거 가능한 앞의 작은 숫자를 모두 제거한 뒤, 현재 숫자를 데크의 뒤에 추가한다.

```java
dq.offer(number.charAt(i));
```

데크에 남은 숫자의 상대적인 순서는 원본 문자열과 같다.

##### 4. 남은 삭제 횟수 처리

숫자가 내림차순이거나 서로 같은 숫자가 연속하면, 앞의 순회에서 `remaining`을 모두 사용하지 못할 수 있다.

이미 데크에 남은 숫자는 앞에서부터 가능한 큰 숫자를 배치한 결과이므로, 뒤쪽 숫자를 남은 횟수만큼 제거한다.

```java
while (remaining > 0) {
    dq.pollLast();
    remaining--;
}
```

##### 5. 결과 문자열 생성

데크의 앞에서부터 숫자를 꺼내 `StringBuilder`에 추가한다.

```java
while (!dq.isEmpty()) {
    sb.append(dq.pollFirst());
}
```

정확히 `k`개를 제거했으므로 결과의 길이는 항상 `number.length() - k`가 된다.

#### 정당성

앞자리의 숫자가 커지면 뒷자리에 어떤 숫자가 오더라도 전체 수는 더 커진다.

현재 숫자가 데크의 마지막 숫자보다 큰데도 마지막 숫자를 남긴다면, 작은 숫자가 더 앞자리를 차지한다. 두 숫자의 순서를 바꾸지 못하므로, 삭제 기회가 있을 때 앞의 작은 숫자를 제거하는 것이 항상 유리하다.

더 큰 숫자가 뒤에 나오지 않아 삭제 횟수가 남았다면, 앞자리를 그대로 유지하고 뒤쪽을 제거하는 것이 가장 큰 수를 만든다. 따라서 이 그리디 선택으로 정확히 `k`개를 제거하면 최댓값을 얻을 수 있다.

#### 시간복잡도

```text
시간복잡도: O(N)
```

각 숫자는 데크에 한 번 추가되고 최대 한 번 제거된다. 내부의 `while`문이 있지만 전체 제거 횟수는 `k`번을 넘지 않는다. 결과 문자열을 만드는 순회도 `O(N)`이다.

```text
숫자 순회 및 데크 작업: O(N)
결과 문자열 생성:       O(N)

O(N) + O(N)
→ O(N)
```

#### 공간복잡도

```text
공간복잡도: O(N)
```

데크에 최대 `N`개의 문자가 저장되고, 결과를 만들기 위한 `StringBuilder`도 입력 길이에 비례하는 공간을 사용한다.

#### 개선 가능한 부분

- 첫 번째 숫자를 미리 넣지 않고, 빈 데크에서 인덱스 0부터 모두 같은 로직으로 처리하면 초기화와 반복 구조를 단순화할 수 있다.
- `StringBuilder`를 스택처럼 사용하면 `Character` 객체를 다루는 `Deque<Character>`를 사용하지 않고도 뒤쪽 문자를 비교·삭제할 수 있다. 이를 통해 구현과 결과 생성 과정을 더 간결하게 만들 수 있다.
- 현재 풀이의 시간복잡도는 `O(N)`으로, 입력을 최소 한 번은 확인해야 하므로 점근적으로 더 개선하기 어렵다.

#### 시행착오

- 초기 코드에서는 현재 숫자가 더 클 때 앞의 작은 숫자를 제거하는 로직만 작성하고, 순회가 끝난 뒤 `remaining`이 남은 경우를 처리하지 않았다.
  - **원인:** 입력이 내림차순인 `"98765"`나 같은 숫자로 이루어진 문자열에서는 `dq.peekLast() < number.charAt(i)` 조건이 충족되지 않음. 그 결과 숫자를 `k`개 제거하지 않은 원본 길이의 문자열을 반환했다.
  - **해결:** 전체 순회 후 `remaining > 0`인 동안 데크의 뒤쪽 숫자를 제거했다. 현재 데크는 뒤쪽 숫자가 앞의 숫자보다 크지 않으므로, 뒤에서 제거해야 가장 큰 결과가 남는다.
  - **이후 주의할 점:** 문제가 “최대 `k`개”가 아니라 “정확히 `k`개”를 제거하라고 요구하는지 확인해야 한다. 그리디 선택이 발생하지 않는 내림차순, 모든 값이 같은 경우와 같은 경계 사례도 반드시 검증해야 한다.
