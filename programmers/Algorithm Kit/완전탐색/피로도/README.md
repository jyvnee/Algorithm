# 피로도

## 알고리즘 분류

- 완전탐색 (Brute Force)
- 백트래킹 (DFS / 순열 탐색)

## 문제 정의

- 현재 피로도 `k`, 각 던전의 `[최소 필요 피로도, 소모 피로도]` 배열 `dungeons`가 주어진다.
- 남은 피로도가 던전의 `최소 필요 피로도` 이상일 때만 그 던전을 탐험할 수 있고, 탐험하면 `소모 피로도`만큼 줄어든다.
- 던전을 도는 **순서는 자유**이며, 각 던전은 하루에 한 번만 돈다.
- 탐험할 수 있는 **최대 던전 수**를 구한다.
- 던전 개수는 최대 8개 → 모든 순서를 시도해도 되는 규모.

## 풀이 기록

### v1

#### 풀이 아이디어

- 던전 개수가 8 이하이므로 **가능한 모든 방문 순서를 재귀로 완전탐색**한다.
- `visited` 배열로 이미 탐험한 던전을 표시하고, 아직 안 갔으면서 지금 피로도로 갈 수 있는 던전을 하나씩 선택해 재귀 진입한다.
- `explore` 함수의 반환값 계약을 **"현재 피로도 상태에서 앞으로 추가로 탐험 가능한 최대 던전 수"** 로 정의한다.
  - 더 갈 수 있는 던전이 없으면 자연스럽게 `0`을 반환한다.
  - 어떤 던전 `i`를 선택하면 `1 + explore(피로도 - 소모, ...)` 이 되고, 모든 선택지 중 최댓값을 취한다.
- `k`가 5,000 이하로 작지만 DP로 쓰기엔 상태가 애매하고(피로도 × 방문집합), 던전 수가 8이라 완전탐색이 가장 단순하고 확실하다.

#### 알고리즘 풀이

```
solution(k, dungeons):
    visited = [false] * n
    return explore(k, visited, dungeons)

explore(fatigue, visited, dungeons):
    best = 0
    for i in 0..n-1:
        if visited[i] : skip                 # 이미 탐험한 던전
        if fatigue < dungeons[i][0] : skip   # 최소 필요 피로도 부족
        visited[i] = true
        best = max(best, 1 + explore(fatigue - dungeons[i][1], visited, dungeons))
        visited[i] = false                   # 백트래킹: 다음 순서 조합을 위해 복구
    return best
```

- 각 재귀 호출은 "지금 갈 수 있는 던전"을 모두 후보로 놓고, 그 던전을 간 뒤의 하위 결과에 `+1`을 더한다.
- `visited[i] = false` 복구가 있어 같은 던전이 서로 다른 순서 조합에서 재사용된다. (다른 경로 기준)
- 재귀가 반환하는 값은 항상 "그 시점 이후 추가 탐험 수"이므로, 어느 레벨에서도 값이 중복 누적되지 않는다.

예시 확인 (`k = 80`, `dungeons = [[80,20],[50,40],[30,10]]`)

```
explore(80): 던전0(필요80) 가능 → 1 + explore(60)
  explore(60): 던전1(필요50) 가능 → 1 + explore(20)
                던전2(필요30) 가능 → 1 + explore(50)
    explore(20): 던전1(필요50) 불가, 던전2(필요30) 불가 → 0
    explore(50): 던전1(필요50) 가능 → 1 + explore(10) = 1 + 0 = 1
  explore(60) = max(1+0, 1+1) = 2
explore(80) = 1 + 2 = 3
```

→ 결과 `3` (기댓값과 일치)

#### 시간복잡도

`O(n · n!)` (n = 던전 개수, n ≤ 8)

- 최악의 경우(모든 던전을 항상 갈 수 있는 경우) 재귀 트리는 n개 원소의 순열을 모두 전개한다 → 리프까지 경로 수 `O(n!)`.
- 각 호출에서 `for` 루프로 후보 던전을 훑는 비용이 `O(n)`.
- n ≤ 8 이므로 `8 · 8! ≈ 322,560` 회 수준으로, 시간 제한에 전혀 문제없다.

#### 공간복잡도

`O(n)`

- `visited` 배열 `O(n)`.
- 재귀 호출 스택 깊이 최대 `n` → `O(n)`.

#### 개선 가능한 부분

- **가지치기(pruning)**: 남은 던전을 전부 돌 수 있는 상태라면 더 재귀하지 않고 바로 `남은 개수`를 반환할 수 있다. 다만 n ≤ 8 이라 실효성은 거의 없다.
- **비트마스크 상태 압축**: `visited` 배열 대신 `int` 비트마스크를 쓰면 방문 상태 복사/전달이 가벼워지고, `(mask, fatigue)` 를 키로 하는 메모이제이션도 가능하다. 하지만 `fatigue` 값 범위(최대 5,000) 때문에 상태 수가 `2^8 × 5001` 로 커지고, 현재 규모에선 이득 없이 코드만 복잡해진다.
- 가독성 측면에서 `dungeons[i][0]`, `dungeons[i][1]` 을 `required`, `cost` 지역 변수로 빼면 의미가 더 명확해진다.

#### 시행착오

- **재귀 반환값의 의미를 명확히 정의하지 않아 결과가 부풀려졌다.**
  - 초기 구현은 `explore(count, fatigue, ...)` 에서 `count`(재귀 깊이)를 파라미터로 넘기고 마지막에 `return answer + count;` 를 했는데, 재귀가 풀리는 매 레벨마다 `count`가 결과에 더해져 실제 던전 수보다 큰 값이 나왔다. (예제에서 3 대신 4 반환)
  - 추가로 `if (allVisit(visited)) return 1;` 처럼 매직 넘버를 반환하고, `answer`를 `-1`로 초기화해 던전을 못 가는 경우 `count - 1` 이 반환되는 등 경계 처리도 어긋나 있었다.
  - **원인**: 함수가 "무엇을 반환하는지"에 대한 계약이 없었다. 깊이(count)와 결과를 한 값에 섞었다.
  - **해결**: 반환값을 **"이 상태에서 추가로 탐험 가능한 최대 수"** 로 통일했다.
    갈 수 있는 던전이 없으면 `0`, 있으면 `1 + 하위 결과`의 최댓값. `count`, `allVisit`, `answer + count` 를 전부 제거했다.
  - **이후 주의점**: 백트래킹 함수를 짤 때 먼저 "이 함수는 무엇을 반환/갱신하는가"를 한 문장으로
    정하고 시작한다. (예: "남은 최대 개수를 반환" 또는 "전역 max를 갱신하고 void")
- 다른 순서 조합을 탐색하려면 재귀 후 `visited[i] = false` 복구가 반드시 필요하다.
