# 최소직사각형

## 알고리즘 분류

정렬(Sort), 그리디(Greedy)

## 풀이 기록

### v1

#### 문제 정의

각 명함은 가로/세로를 자유롭게 회전(눕혀서 수납)할 수 있다. 모든 명함을 회전 없이 혹은 회전해서 담을 수 있는 가장 작은 직사각형 지갑의 크기(가로 x 세로)를 구한다.

#### 풀이 아이디어

명함을 회전시킬 수 있으므로, 각 명함의 두 변 중 짧은 변을 지갑의 한 축(가로)에, 긴 변을 다른 한 축(세로)에 대응시키는 방향으로 통일하면 비교가 단순해진다.

- 각 명함의 [w, h]를 오름차순 정렬하여 항상 `sizes[i][0]`이 짧은 변, `sizes[i][1]`이 긴 변이 되도록 만든다.
- 모든 명함에서 짧은 변의 최댓값(`rowMax`)과 긴 변의 최댓값(`colMax`)을 각각 구한다.
- 지갑의 크기는 `rowMax * colMax`가 된다.

이 방식이 성립하는 이유는, 모든 명함을 "짧은 변은 가로, 긴 변은 세로"로 통일해서 눕히면 어떤 명함이든 `rowMax`와 `colMax`로 만든 지갑 안에 반드시 들어가기 때문이다. 각 명함마다 개별적으로 정렬해 짧은 변/긴 변을 결정하므로 전체 원소를 한 번씩만 순회하면 되고, 모든 조합을 비교하는 완전탐색 없이 문제를 해결할 수 있다.

#### 알고리즘 풀이

1. `rowMax`, `colMax`를 0으로 초기화한다.
2. `sizes` 배열을 순회하며 각 명함 `sizes[i]`에 대해:
   - `Arrays.sort(sizes[i])`로 정렬하여 `sizes[i][0]`을 짧은 변, `sizes[i][1]`을 긴 변으로 만든다.
   - `rowMax`를 짧은 변들의 최댓값으로 갱신한다.
   - `colMax`를 긴 변들의 최댓값으로 갱신한다.
3. `rowMax * colMax`를 반환한다.

#### 시간복잡도

O(N log 1) ≈ O(N)

- 명함 개수를 N이라 할 때, 각 명함마다 원소가 2개뿐인 배열을 정렬하므로 정렬 비용은 상수 시간이다.
- 전체 N개의 명함을 한 번씩 순회하므로 O(N)

#### 공간복잡도

O(1)

- `rowMax`, `colMax`와 같은 몇 개의 변수만 사용하며, 입력 배열을 제자리에서(in-place) 정렬하므로 추가 메모리를 거의 사용하지 않는다.

#### 개선 가능한 부분

- `Arrays.sort(sizes[i])`가 입력 배열 `sizes`를 직접 변경(mutate)한다. 함수 외부에서 원본 배열을 재사용해야 하는 경우 부작용이 발생할 수 있으므로, 필요하다면 `sizes[i][0] > sizes[i][1]`일 때 두 값을 직접 swap하는 방식으로 대체해 정렬 API 호출 없이 처리할 수 있다.
- 현재 구현은 이미 O(N)으로 충분히 효율적이며, 별도의 시간복잡도 개선 여지는 없다.
