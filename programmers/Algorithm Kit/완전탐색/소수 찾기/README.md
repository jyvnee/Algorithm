# 소수 찾기

## 알고리즘 분류

- 완전탐색
- 순열
- DFS(깊이 우선 탐색)
- 소수 판별
- HashSet을 이용한 중복 제거

## 풀이 기록

### v1

#### 문제 정의

주어진 숫자 조각을 각각 최대 한 번씩 사용하여 만들 수 있는 모든 정수를 탐색한다. 그중 소수인 값의 개수를 구한다.

같은 숫자가 여러 번 나오거나 `0`이 앞에 붙으면 서로 다른 탐색 경로에서 같은 정수가 만들어질 수 있으므로, 중복을 제거한 뒤 개수를 세어야 한다.

#### 풀이 아이디어

`visited` 배열로 각 숫자 조각의 사용 여부를 관리하며 DFS를 수행한다. DFS에서 아직 사용하지 않은 숫자 조각을 하나 선택해 현재 숫자의 뒤에 붙인다.

```java
next = current * 10 + digit;
```

숫자 조각을 하나 선택할 때마다 현재 정수를 소수 판별하므로, 1개의 조각으로 만든 수부터 모든 조각을 사용한 수까지 모두 검사할 수 있다.

소수로 판정된 값은 `HashSet<Integer>`에 저장한다. 이를 통해 같은 숫자 조각으로 생긴 중복 값과 선행 `0`으로 인해 생긴 중복 값을 자동으로 제거한다.

#### 알고리즘 풀이

1. `numbers`의 각 문자를 `digits` 배열에 저장한다.
2. `dfs(0)`을 호출해 빈 수에서 탐색을 시작한다.
3. DFS에 진입할 때 현재 숫자가 소수인지 판별한다.
4. 소수라면 `primes`에 추가한다.
5. 아직 사용하지 않은 모든 숫자 조각을 하나씩 선택한다.
6. 선택한 조각을 사용 처리한 뒤 새 숫자로 DFS를 재귀 호출한다.
7. 재귀 호출이 끝나면 사용 처리를 취소하여 다른 순열을 탐색한다.
8. 탐색이 완료되면 `primes.size()`를 반환한다.

소수 판별은 2부터 제곱근까지의 수로만 나누어 본다. 약수가 존재한다면 제곱근을 기준으로 짝을 이루기 때문에 그 이상은 확인할 필요가 없다.

```java
for (int divisor = 2; divisor <= n / divisor; divisor++)
```

`divisor * divisor <= n`과 같은 조건이지만, 곱셈으로 인한 정수 오버플로우 가능성을 피하는 표현이다.

#### 시간복잡도

숫자 조각의 개수를 `N`, 만들 수 있는 최댓값을 `M`이라고 하자.

생성하는 순열의 총개수는 다음과 같다.

```text
P(N, 1) + P(N, 2) + ... + P(N, N)
```

각 탐색 상태에서 `N`개의 숫자 조각을 확인하고, 최대 `√M`까지 소수 판별을 수행한다. 따라서 전체 시간복잡도는 다음과 같다.

```text
O((P(N, 1) + P(N, 2) + ... + P(N, N)) × (N + √M))
```

`N`은 최대 7이므로 완전탐색이 가능하다.

#### 공간복잡도

- `visited`, `digits`, 재귀 호출 스택: `O(N)`
- 소수를 저장하는 `HashSet`: 최악의 경우 `O(P(N, 1) + ... + P(N, N))`

따라서 전체 공간복잡도는 생성 가능한 서로 다른 소수의 개수를 `U`라고 할 때 `O(N + U)`이다. 최악의 경우는 순열의 총개수에 비례한다.

#### 개선 가능한 부분

- `digits` 배열은 반복문 대신 `numbers.toCharArray()`로 간단하게 생성할 수 있다.
- 같은 숫자 조각이 여러 개이면 같은 순열을 여러 번 탐색한 뒤 `HashSet`에서 중복을 제거한다. 숫자를 정렬하고 각 DFS 깊이에서 이미 선택한 같은 값을 건너뛰면 중복 탐색을 줄일 수 있다.
- 첫 자리에서 `0`을 선택하는 경로를 생략하면 `01`, `011` 등이 기존의 `1`, `11`과 같은 정수로 변환되는 중복 탐색을 줄일 수 있다.
- 현재 제한에서는 제곱근까지 나누는 방식으로 충분하다. 만들 수 있는 최댓값까지 에라토스테네스의 체를 미리 구하는 방법도 있지만, 최대 약 1,000만 크기의 배열이 필요하므로 메모리와 전처리 비용을 비교해야 한다.
