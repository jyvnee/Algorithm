# 더 맵게

## 알고리즘 분류

힙(Priority Queue)

## 풀이 기록

### v1

#### 문제 정의

스코빌 지수가 가장 낮은 두 음식을 `first + second * 2` 규칙으로 섞는 과정을 모든 음식의 스코빌 지수가 K 이상이 될 때까지 반복할 때, 필요한 최소 섞기 횟수를 구한다. 남은 음식이 하나뿐인데도 K 이상으로 만들 수 없다면 -1을 반환한다.

#### 풀이 아이디어

가장 스코빌 지수가 낮은 두 음식을 반복적으로 골라 섞어야 하므로, 최솟값을 빠르게 꺼낼 수 있는 자료구조가 필요하다. `PriorityQueue`(최소 힙)를 사용하면 매번 O(log N)에 최솟값을 꺼내고 새로운 값을 넣을 수 있어 적합하다.

- 모든 스코빌 지수를 최소 힙에 삽입한다.
- 힙의 최솟값이 K 미만인 동안 반복한다.
  - 가장 낮은 값(`first`)과 두 번째로 낮은 값(`second`)을 꺼낸다.
  - 섞을 두 번째 음식이 없다면(`pq.isEmpty()`) 모든 음식을 K 이상으로 만들 수 없으므로 -1을 반환한다.
  - `first + second * 2`를 계산해 다시 힙에 넣는다.
  - 섞은 횟수(`answer`)를 1 증가시킨다.
- 반복이 끝나면 섞은 횟수를 반환한다.

#### 알고리즘 풀이

1. `scoville` 배열의 모든 원소를 `PriorityQueue<Integer>`(최소 힙)에 삽입한다.
2. `while (pq.peek() < K && pq.size() > 0)` 조건으로 최솟값이 K보다 작은 동안 반복한다.
   - 최솟값 `first`를 꺼낸다.
   - 힙이 비어 있으면 더 이상 섞을 음식이 없다는 뜻이므로 `-1`을 반환한다.
   - 두 번째로 낮은 값 `second`를 꺼낸다.
   - 새로운 스코빌 지수 `first + second * 2`를 힙에 다시 넣는다.
   - `answer`를 1 증가시킨다.
3. 힙의 최솟값이 K 이상이 되면 반복을 종료하고 `answer`를 반환한다.

#### 시간복잡도

O(N log N)

- 모든 원소를 힙에 삽입: O(N log N)
- 반복문에서 매번 poll/offer를 수행하며 이는 최대 N-1번 반복: O(N log N)
- 전체: O(N log N) + O(N log N) → O(N log N)

#### 공간복잡도

O(N)

- 모든 스코빌 지수를 저장하는 힙의 크기가 N에 비례한다.

#### 개선 가능한 부분

- `while (pq.peek() < K && pq.size() > 0)` 조건은 `pq.peek()`을 먼저 평가한 뒤 `size()`를 확인하는 순서로, 의도(빈 큐 방어)와 실제 동작이 어긋난다. 힙의 크기는 반복마다 1씩 줄어들다가 반복 중간에 `isEmpty()` 체크로 먼저 걸러지기 때문에 실제로 `pq.peek()`이 빈 큐에서 호출되는 경우는 없지만, 조건의 의도를 명확히 하려면 `pq.size() > 0 && pq.peek() < K` 순서로 작성하는 것이 더 안전하고 가독성이 좋다.
- 배열 전체를 힙에 넣는 대신 힙 생성자에 배열을 바로 전달하면(`new PriorityQueue<>(Arrays.stream(scoville).boxed().toList())` 등) 코드가 간결해질 수 있으나, 오토박싱 비용을 고려하면 현재 방식과 성능 차이는 크지 않다.
