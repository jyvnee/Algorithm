# 전화번호 목록

## 알고리즘 분류

- 정렬
- 해시
- 문자열
- 접두어 판별

## 풀이 기록

### v1

#### 문제 정의

전화번호를 사전순으로 정렬한 뒤, 한 전화번호가 바로 다음 전화번호의 접두어인지 확인한다. 접두어 관계인 두 번호가 하나라도 존재하면 `false`, 존재하지 않으면 `true`를 반환한다.

#### 풀이 아이디어

문자열을 사전순으로 정렬하면 공통 접두어를 가진 전화번호들이 서로 가까운 위치에 모인다.

예를 들어 `"119"`가 어떤 번호의 접두어라면 `"119"`로 시작하는 번호들은 정렬 결과에서 `"119"` 바로 뒤부터 연속해서 배치된다. 따라서 모든 전화번호 조합을 비교할 필요 없이, 인접한 두 번호만 비교해도 접두어 관계를 찾을 수 있다.

- `Arrays.sort()`로 전화번호 배열을 사전순 정렬한다.
- 앞 번호 `phone_book[i]`가 다음 번호 `phone_book[i + 1]`의 접두어인지 `startsWith()`로 검사한다.
- 접두어 관계가 확인되면 즉시 `false`를 반환한다.
- 끝까지 발견되지 않으면 `true`를 반환한다.

#### 알고리즘 풀이

1. `phone_book`을 사전순으로 정렬한다.
2. 첫 번째 전화번호부터 마지막 바로 앞 전화번호까지 순회한다.
3. `phone_book[i + 1].startsWith(phone_book[i])`를 검사한다.
4. 결과가 `true`라면 앞 번호가 뒤 번호의 접두어이므로 즉시 `false`를 반환한다.
5. 모든 인접한 번호를 확인한 뒤에도 접두어 관계가 없다면 `true`를 반환한다.

접두어가 될 수 있는 번호는 항상 자신보다 긴 번호보다 사전순으로 앞에 위치한다. 또한 같은 접두어를 공유하는 문자열은 정렬했을 때 연속해서 놓이므로, 앞 번호와 바로 다음 번호만 검사하는 것으로 충분하다.

#### 시간복잡도

전화번호의 개수를 `N`, 전화번호 하나의 최대 길이를 `L`이라고 하면 다음과 같다.

- 정렬: 문자열 비교에 최대 `O(L)`이 걸리므로 `O(N log N × L)`
- 인접 원소 검사: `startsWith()`가 최대 `O(L)`이고 최대 `N - 1`번 수행되므로 `O(N × L)`

따라서 전체 시간복잡도는 다음과 같다.

```text
O(N log N × L) + O(N × L)
→ O(N log N × L)
```

문제에서 전화번호 길이는 최대 20으로 제한되므로 `L`을 상수로 보면 일반적으로 `O(N log N)`으로 표현할 수 있다.

#### 공간복잡도

`Arrays.sort(Object[])`가 정렬 과정에서 사용하는 임시 배열을 고려하면 공간복잡도는 `O(N)`이다. 풀이에서 별도로 생성하는 자료구조는 없으며, 입력 배열 자체를 정렬한다.

#### 개선 가능한 부분

- 현재 풀이는 코드가 짧고, 정렬 후 한 번의 순회만 수행하므로 구현이 단순하다.
- 입력 배열을 직접 정렬하므로 원래 순서를 보존해야 한다면 배열을 복사한 뒤 정렬해야 한다. 이 경우 명시적으로 `O(N)`의 추가 공간이 필요하다.
- 트라이를 사용하면 모든 전화번호의 문자를 한 번씩 처리하여 이론적으로 `O(N × L)` 시간에 해결할 수 있다. 다만 노드 객체와 자식 참조로 인한 메모리 사용량 및 구현 복잡도가 크게 증가할 수 있다.
- `HashSet`에 전화번호를 저장한 뒤 각 번호의 모든 접두어를 조회하는 방법도 가능하다. Java에서 `substring()` 생성과 해시 계산 비용까지 고려하면 최악의 경우 `O(N × L²)`이 될 수 있지만, `L`이 최대 20이므로 실용적인 대안이다.

### v2

#### 문제 정의

모든 전화번호를 해시 집합에 저장하고, 각 전화번호에서 만들 수 있는 진접두어가 집합에 존재하는지 확인한다. 다른 전화번호와 일치하는 접두어가 하나라도 있으면 `false`, 없으면 `true`를 반환한다.

#### 풀이 아이디어

`HashSet`은 문자열의 존재 여부를 평균 `O(1)`에 확인할 수 있다. 먼저 모든 전화번호를 `HashSet`에 저장한 뒤, 각 전화번호의 앞부분을 한 글자씩 늘려 가며 접두어를 만든다. 만들어진 접두어가 집합에 있다면 해당 접두어 자체가 전화번호부에 등록된 번호이므로 접두어 관계가 성립한다.

자기 자신은 비교 대상에서 제외해야 한다. 따라서 접두어 길이는 `1`부터 `phone.length() - 1`까지만 확인한다.

#### 알고리즘 풀이

1. `HashSet<String>`을 생성한다.
2. `phone_book`의 모든 전화번호를 집합에 저장한다.
3. 각 전화번호를 순회하며 길이가 `1` 이상이고 전체 길이보다 짧은 모든 접두어를 `substring(0, i)`로 생성한다.
4. 생성한 접두어가 `phoneSet`에 존재하면 다른 전화번호가 현재 번호의 접두어이므로 즉시 `false`를 반환한다.
5. 모든 전화번호의 접두어를 검사한 뒤에도 일치하는 번호가 없다면 `true`를 반환한다.

예를 들어 `"1195524421"`을 검사할 때 `"1"`, `"11"`, `"119"` 순서로 접두어를 조회한다. 이때 `"119"`가 집합에 존재하면 더 긴 접두어를 확인할 필요 없이 `false`를 반환한다.

#### 시간복잡도

전화번호의 개수를 `N`, 전화번호 하나의 최대 길이를 `L`이라고 하면 다음과 같다.

- 해시 집합 생성: 각 문자열의 해시 계산까지 고려하면 `O(N × L)`
- 접두어 검사: 전화번호 하나에서 최대 `L - 1`개의 접두어를 생성한다.
- Java의 `substring()`은 접두어 길이에 비례해 새 문자열을 만들고, 새 문자열의 해시 계산도 길이에 비례한다.

전화번호 하나에 대한 접두어 처리 비용은 다음과 같다.

```text
O(1 + 2 + ... + (L - 1))
→ O(L²)
```

따라서 평균적인 전체 시간복잡도는 다음과 같다.

```text
O(N × L) + O(N × L²)
→ O(N × L²)
```

문제에서 `L`은 최대 20이므로 길이를 상수로 보면 실질적으로 `O(N)`에 가깝게 동작한다. 위 분석은 해시 충돌이 과도하게 발생하지 않아 `HashSet.contains()`가 평균 `O(1)`에 동작한다고 가정한다.

#### 공간복잡도

`HashSet`에는 입력 배열에 이미 존재하는 문자열 객체의 참조를 저장하므로 보조 공간복잡도는 `O(N)`이다. 전화번호 문자열 자체의 저장 공간까지 포함해 표현하면 `O(N × L)`이며, 검사 중 생성되는 접두어 문자열은 일시적으로 최대 `O(L)`의 추가 공간을 사용한다.

#### 개선 가능한 부분

- `substring()`을 반복 호출하므로 짧은 생명주기의 문자열 객체가 많이 생성된다. 다만 전화번호 길이가 최대 20이어서 제한 범위에서는 부담이 크지 않다.
- 성능뿐 아니라 구현 단순성과 메모리 사용량을 함께 고려하면 v1의 정렬 방식도 좋은 선택이다.

#### v1과의 비교

- v1은 전화번호 배열을 사전순으로 정렬한 뒤 인접한 번호만 비교한다.
- v2는 모든 전화번호를 `HashSet`에 저장한 뒤 각 번호의 가능한 접두어를 직접 조회한다.
- v1은 입력 배열의 순서를 변경하지만, v2는 입력 배열을 변경하지 않는다.
- v2는 해시 집합에 `O(N)`개의 참조를 추가로 저장하고, 접두어 문자열을 생성하는 비용이 발생한다.
- 전화번호의 최대 길이가 20으로 작기 때문에 v2의 `O(N × L²)` 접두어 검사도 제한 범위에서 충분히 실용적이다.
