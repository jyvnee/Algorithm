# 베스트앨범

## 알고리즘 분류

해시(HashMap), 정렬

## 풀이 기록

### v1

#### 문제 정의

- 장르별 총 재생 횟수가 많은 장르를 먼저 수록한다.
- 같은 장르 내에서는 재생 횟수가 많은 노래를 먼저 수록하되, 장르당 최대 2곡만 수록한다.
- 재생 횟수가 같다면 고유 번호가 낮은 노래를 먼저 수록한다.

#### 풀이 아이디어

- 장르별로 `총 재생 횟수`, `재생 횟수 1위 노래`, `재생 횟수 2위 노래`만 알면 정답을 구성할 수 있으므로, 노래 전체를 장르별로 모아 정렬하는 대신 한 번의 순회로 장르별 상위 2곡을 갱신하는 방식을 사용했다.
- `HashMap<String, GenreInfo>`로 장르별 집계 정보를 관리한다.
  - `GenreInfo`는 `totalPlay`(장르 총 재생 횟수), `first`(1위 노래), `second`(2위 노래)를 가진다.
- 노래를 순서대로 순회하며 해당 장르의 `totalPlay`를 누적하고, 현재 노래가 `first`보다 우수하면 `first`를 `second`로 내리고 현재 노래를 `first`로 교체, 그렇지 않고 `second`보다 우수하면 `second`만 교체한다.
- 우수함의 기준(`isBetter`)은 재생 횟수가 더 많으면 우수, 같다면 고유 번호가 더 작으면 우수로 판단한다.
  - 노래를 고유 번호(인덱스) 순서대로 순회하므로, 재생 횟수가 같을 경우 나중에 들어온 노래(id가 더 큼)는 항상 `isBetter`가 `false`가 되어 먼저 들어온 노래(낮은 id)가 유지된다. 이를 통해 별도의 동점 처리 로직 없이 "재생 횟수가 같으면 고유 번호가 낮은 노래 우선" 조건을 자연스럽게 만족한다.
- 순회가 끝나면 장르 목록을 `totalPlay` 내림차순으로 정렬하고, 각 장르의 `first`, `second`를 순서대로 결과에 담는다.

#### 알고리즘 풀이

1. `genres`, `plays`를 함께 순회하며 각 노래를 해당 장르의 `GenreInfo`에 반영한다.
   - `map.putIfAbsent(genre, new GenreInfo())`로 장르 최초 등장 시 정보를 초기화한다.
   - `totalPlay += play`로 장르 총 재생 횟수를 누적한다.
   - 현재 노래(`current`)가 `first`보다 우수하면 `second = first`, `first = current`로 교체한다.
   - 그렇지 않고 `current`가 `second`보다 우수하면 `second = current`로 교체한다.
2. 장르 목록(`map.keySet()`)을 `totalPlay` 내림차순으로 정렬한다.
3. 정렬된 장르 순서대로 `first`, `second`의 `id`를 결과 리스트에 추가한다. 장르에 곡이 하나뿐이면 `second`가 `null`이므로 추가하지 않는다.
4. 결과 리스트를 배열로 변환하여 반환한다.

#### 시간복잡도

O(N + G log G) (N: 노래 개수, G: 장르 개수, G < 100)

- 노래 순회 및 장르별 집계: O(N)
- 장르 목록 정렬: O(G log G)
- 결과 구성: O(G)

G가 100 미만으로 매우 작으므로 사실상 O(N)에 수렴한다.

#### 공간복잡도

O(N + G)

- 입력 배열 `genres`, `plays`: O(N)
- 장르별 집계를 위한 `HashMap`: 장르당 상수 크기 정보만 저장하므로 O(G)
- 결과 리스트: 장르당 최대 2곡이므로 O(G)

#### 개선 가능한 부분

- 현재 풀이는 장르별 상위 2곡만 유지하는 방식으로 이미 O(N)에 가까운 효율적인 구조를 가지고 있어 시간복잡도 측면에서 크게 개선할 부분은 없다.
- `isBetter` 메서드가 `first`/`second` 갱신 시 두 번 호출되는 구조인데, 이는 가독성을 위한 것으로 성능에 미치는 영향은 미미하다.
- `Song`, `GenreInfo`를 별도 클래스로 분리해 가독성을 높였으나, 필요하다면 배열 기반으로 더 메모리 효율적으로 구현할 수도 있다(다만 가독성이 낮아지므로 트레이드오프가 있다).
