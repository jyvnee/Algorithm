# 타겟 넘버

## 알고리즘 분류

- 깊이 우선 탐색(DFS)
- 재귀
- 완전 탐색

## 풀이 기록

### v1

#### 문제 정의

`numbers`의 각 숫자를 순서대로 한 번씩 사용하면서 `+`나 `-`를 적용한다. 모든 숫자를 사용했을 때 계산 결과가 `target`과 같은 경우의 수를 구한다.

#### 풀이 아이디어

각 숫자에 대해 더하는 경우와 빼는 경우 두 가지로 나누어 DFS를 수행한다.

`dfs` 함수는 다음 상태를 관리한다.

- `current`: 현재까지 계산한 합
- `index`: 이번에 사용할 숫자의 위치

어떤 분기에서 모든 숫자를 사용했다면 `current`와 `target`을 비교한다. 두 값이 같으면 해당 분기가 하나의 유효한 방법이므로 `1`, 다르면 `0`을 반환한다. 각 하위 호출이 반환한 값을 더하면 전체 방법의 수가 된다.

#### 알고리즘 풀이

1. `current = 0`, `index = 0`에서 DFS를 시작한다.
2. `numbers[index]`를 `current`에 더한 후 `index + 1`로 이동한다.
3. 같은 숫자를 `current`에서 뺀 후 `index + 1`로 이동한다.
4. 두 재귀 호출이 반환한 유효한 방법의 수를 더해 반환한다.
5. `index == numbers.length`가 되면 `current == target`인지 확인하여 `1` 또는 `0`을 반환한다.

#### 시간복잡도

**O(2^N)**

각 숫자마다 더하기와 빼기 두 가지 선택지가 있다. 숫자가 `N`개일 때 탐색하는 최종 경로는 `2^N`개이므로 시간복잡도는 `O(2^N)`이다.

#### 공간복잡도

**O(N)**

별도의 자료구조를 사용하지 않으며, 재귀 호출 깊이는 숫자의 개수와 같은 `N`이다. 따라서 호출 스택에 필요한 공간은 `O(N)`이다.

#### 개선 가능한 부분

- `java.util.*`에서 가져온 클래스를 사용하지 않으므로 import문을 제거할 수 있다.
- `dfs` 메서드는 `solution` 외부에서 사용하지 않으므로 `private`으로 제한하면 의도가 더 명확해진다.
- 나머지 숫자의 합을 미리 계산하면 현재 합에서 `target`에 도달할 수 없는 분기를 조기에 중단할 수 있다. 다만 모든 조합을 확인해야 하는 입력이 존재하므로 최악의 시간복잡도는 여전히 `O(2^N)`이다.
- `N`이 최대 20이므로 최대 약 100만 개의 조합을 탐색하는 현재 방식으로도 제한 내에서 충분히 해결할 수 있다.

#### 시행착오

- 초기에 두 재귀 호출의 인자로 `++index`를 사용했다.
- Java는 `+` 연산자의 피연산자를 왼쪽부터 평가한다. 따라서 첫 번째 재귀 호출을 만들며 `index`가 증가하고, 첫 호출이 끝난 뒤 두 번째 호출은 변경된 `index`를 사용하게 된다.
- 이로 인해 두 분기가 서로 다른 숫자를 처리하고, 마지막 인덱스에서는 배열 범위를 벗어날 수 있다.
- `++index`를 `index + 1`로 변경하여 현재 함수의 `index`를 변경하지 않고, 두 분기가 모두 같은 다음 인덱스로 이동하도록 수정했다.
- 재귀 호출의 인자에서는 전위·후위 증가와 같이 현재 상태를 변경하는 표현식을 피하고, `index + 1`처럼 부작용이 없는 값을 전달하는 것이 안전하다.
