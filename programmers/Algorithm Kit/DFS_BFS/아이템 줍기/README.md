# 아이템 줍기

## 알고리즘 분류

- 그래프 탐색
- 너비 우선 탐색(BFS)
- 격자 그래프
- 좌표 확장

## 풀이 기록

### v1

#### 문제 정의

여러 직사각형을 합쳐 만든 지형의 바깥 테두리만 따라 이동할 때, 캐릭터의 위치에서 아이템의 위치까지의 최단 거리를 구해야 한다.

직사각형이 겹치면서 생기는 내부 영역과 이동 가능한 외곽선을 구분해야 하며, 서로 가까이 놓인 테두리를 잘못 연결하지 않는 것이 핵심이다.

#### 풀이 아이디어

좌표를 그대로 격자에 표시하면 실제로는 떨어진 두 테두리가 서로 인접한 칸처럼 표현될 수 있다. 이를 방지하기 위해 모든 좌표를 2배로 확장한다.

확장한 직사각형 영역을 모두 `2`로 채운 다음, 각 칸의 주변 8방향을 확인한다.

- 현재 칸이 직사각형 영역인 `2`이다.
- 주변에 외부 영역인 `0`이 존재한다.
- 주변에 직사각형 영역인 `2`도 존재한다.

위 조건을 만족하는 칸을 이동 가능한 테두리인 `1`로 변경한다. 이후 테두리 칸만 상하좌우로 이동하는 격자 그래프를 만들고 BFS를 수행한다.

BFS에서 처음 아이템 위치에 도착했을 때의 거리가 최단 거리다. 모든 좌표를 2배로 확장했으므로 마지막 거리를 2로 나누어 반환한다.

#### 알고리즘 풀이

1. 크기가 `102 × 102`인 격자를 생성한다.
2. 각 직사각형의 시작점과 끝점 좌표를 2배로 변환한다.
3. 변환된 직사각형이 차지하는 모든 칸을 `2`로 채운다.
   - 여러 직사각형이 겹치는 영역도 동일하게 `2`로 유지된다.
4. 격자의 각 칸을 순회하며 주변 8방향을 검사한다.
   - 주변에 `0`과 `2`가 모두 존재하는 직사각형 칸은 외부와 내부의 경계이므로 `1`로 변경한다.
5. 캐릭터의 확장 좌표를 BFS 큐에 넣고 방문 처리한다.
6. 상하좌우 중 값이 `1`이고 아직 방문하지 않은 칸으로 이동한다.
7. 아이템의 확장 좌표에 도착하면 이동 거리를 2로 나누어 반환한다.

#### 시간복잡도

직사각형의 개수를 `R`, 확장된 한 축의 최대 크기를 `C`라고 하자.

- 직사각형 영역 표시: `O(R × C²)`
- 테두리 판별: 각 칸에서 고정된 8방향을 확인하므로 `O(C²)`
- BFS: 각 칸을 최대 한 번 방문하므로 `O(C²)`

따라서 전체 시간복잡도는 다음과 같다.

```text
O(R × C²) + O(C²) + O(C²)
→ O(R × C²)
```

이 문제에서는 `R ≤ 4`, `C ≤ 100`으로 제한되어 있다.

#### 공간복잡도

격자와 방문 배열이 각각 `O(C²)`의 공간을 사용한다. BFS 큐에도 최악의 경우 `O(C²)`개의 위치가 들어갈 수 있다.

```text
공간복잡도: O(C²)
```

#### 개선 가능한 부분

- 4방향 및 8방향 배열을 반복문 내부에서 매번 생성하지 않고 클래스 상수로 선언하면 불필요한 객체 생성을 줄일 수 있다.
- `102`와 같은 숫자를 상수로 선언하면 좌표 확장 범위의 의미가 더 분명해진다.
- 현재는 주변 값을 검사해 테두리를 판별한다. 모든 직사각형 영역을 채운 뒤 각 직사각형의 내부만 제거하는 방식으로도 외곽선을 더 직접적으로 표현할 수 있다.

#### 시행착오

- 처음에는 직사각형의 내부와 테두리를 모두 `1`로 표시한 뒤, 현재 진행 방향과 주변 칸만 보고 테두리를 따라가려고 했다.
  - **원인:** 겹친 직사각형의 내부에도 `1`이 존재하므로 주변에 이동 후보가 여러 개일 때 실제 외곽선을 구분할 수 없었다.
  - **해결:** 직사각형 영역과 최종 테두리를 서로 다른 값으로 구분하고, 테두리만 대상으로 BFS를 수행했다.
  - **주의:** 이동 과정에서 방향을 추측하기보다 탐색 전에 이동 가능한 그래프를 정확하게 구성해야 한다.
- 도착 여부를 `curX != itemX && curY != itemY`로 검사하여 x 또는 y 중 하나만 같아져도 탐색이 끝나는 문제가 있었다.
  - **해결:** 두 좌표가 모두 같을 때만 도착하도록 조건을 수정하고, 최종적으로 BFS의 좌표 비교로 대체했다.
- 진행 방향 계산에서 앞쪽을 `(dir + 2) % 4`로 계산하여 실제로는 뒤쪽을 바라보는 문제가 있었다.
  - **해결:** 방향을 직접 추적하는 방식을 제거하고 BFS의 상하좌우 탐색으로 단순화했다.
- 잘못된 방향으로 직진하면서 격자 밖으로 나가 음수 인덱스를 조회해 `ArrayIndexOutOfBoundsException`이 발생했다.
  - **원인:** 앞이 이동 불가능한 칸이어도 일부 주변 상태에서는 기본값으로 직진 방향을 선택했다.
  - **해결:** 외곽선인 `1`인 칸만 큐에 추가하도록 변경하여 지형 밖으로 이동하지 않게 했다.
- 원래 크기의 좌표에서는 가까운 테두리끼리 붙어 있는 것처럼 인식될 가능성이 있었다.
  - **해결:** 모든 좌표와 시작점, 아이템 위치를 2배로 확장하고, 계산된 거리를 마지막에 2로 나누었다.
