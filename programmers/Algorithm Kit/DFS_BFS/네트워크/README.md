# 네트워크

## 알고리즘 분류

- 너비 우선 탐색(BFS)
- 그래프 탐색
- 연결 요소

## 풀이 기록

### v1

#### 문제 정의

컴퓨터 사이의 연결 관계가 주어졌을 때, 서로 직간접적으로 연결된 컴퓨터 집합인 네트워크의 개수를 구한다.

#### 풀이 아이디어

`computers`를 인접 행렬로 보고, 아직 방문하지 않은 컴퓨터에서 BFS를 시작한다.

한 컴퓨터에서 BFS를 수행하면 그 컴퓨터와 직간접적으로 연결된 모든 컴퓨터를 방문할 수 있다. 따라서 새로운 BFS를 시작한 횟수가 서로 분리된 연결 요소, 즉 네트워크의 개수와 같다.

탐색에는 다음 자료구조를 사용한다.

- `boolean[] visited`: 각 컴퓨터의 방문 여부를 저장한다.
- `Deque<Integer>`: 다음에 탐색할 컴퓨터를 관리하는 BFS 큐로 사용한다.

큐에는 `LinkedList` 대신 `ArrayDeque`를 사용하여 양 끝 삽입과 삭제를 효율적으로 처리한다.

#### 알고리즘 풀이

1. 크기가 `n`인 `visited` 배열과 네트워크 개수를 저장할 `networkCount`를 초기화한다.
2. 모든 컴퓨터를 차례로 확인한다.
3. 현재 컴퓨터를 아직 방문하지 않았다면 해당 컴퓨터를 시작점으로 BFS를 수행하고 `networkCount`를 1 증가시킨다.
4. BFS를 시작할 때 시작 컴퓨터를 큐에 넣고 즉시 방문 처리한다.
5. 큐에서 컴퓨터 하나를 꺼낸 뒤 인접 행렬의 해당 행을 순회한다.
6. 현재 컴퓨터와 연결되어 있으면서 아직 방문하지 않은 컴퓨터를 방문 처리하고 큐에 넣는다.
7. 큐가 빌 때까지 탐색하여 하나의 네트워크에 속한 모든 컴퓨터를 방문한다.
8. 전체 순회가 끝나면 `networkCount`를 반환한다.

컴퓨터를 큐에 넣는 시점에 방문 처리하므로 같은 컴퓨터가 큐에 중복으로 들어가는 것을 방지할 수 있다.

#### 시간복잡도

**O(N²)**

각 컴퓨터는 한 번만 방문하지만, 컴퓨터를 큐에서 꺼낼 때마다 인접 행렬의 한 행을 길이 `N`만큼 확인한다.

```text
N개의 컴퓨터 × 각 컴퓨터에서 N개의 연결 관계 확인
→ O(N²)
```

#### 공간복잡도

**O(N)**

`visited` 배열이 `O(N)`의 공간을 사용하고, BFS 큐에는 최악의 경우 `N`개의 컴퓨터가 들어갈 수 있어 `O(N)`의 공간을 사용한다. 입력으로 주어진 `computers` 배열은 추가 공간 계산에서 제외한다.

#### 개선 가능한 부분

- 현재 풀이는 인접 행렬을 입력으로 받으므로 모든 연결 관계를 확인하는 `O(N²)` 탐색이 자연스럽고, 문제 제한 내에서 충분히 효율적이다.
- 연결 관계가 인접 리스트로 주어진 희소 그래프라면 `O(N + E)`에 탐색할 수 있다. 그러나 현재 인접 행렬을 인접 리스트로 변환하는 과정 자체가 `O(N²)`이므로 이 문제에서는 실질적인 시간복잡도 개선이 되지 않는다.
- BFS 대신 재귀 또는 스택을 이용한 DFS로도 동일하게 연결 요소의 개수를 구할 수 있다. 현재 BFS는 재귀 깊이에 의존하지 않아 호출 스택 오버플로우를 걱정할 필요가 없다는 장점이 있다.
- `bfs` 메서드에서 `n`을 별도로 전달하지 않고 `computers.length` 또는 `visited.length`를 사용하면 매개변수를 줄일 수 있다.
- 와일드카드 import 대신 실제로 사용하는 `ArrayDeque`와 `Deque`만 명시적으로 import하면 의존성이 더 분명해진다.
