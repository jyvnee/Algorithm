# 퍼즐 조각 채우기

## 알고리즘 분류

- 그래프 탐색
- 너비 우선 탐색(BFS)
- 연결 요소
- 좌표 정규화
- 해싱

## 풀이 기록

### v1

#### 문제 정의

게임 보드의 연결된 빈 공간과 테이블의 연결된 퍼즐 조각을 찾고, 위치와 회전 방향에 관계없이 모양이 같은 경우에만 조각을 사용한다.

하나의 조각은 한 번만 사용할 수 있으며, 뒤집기는 허용되지 않고 90도 단위의 회전만 허용된다. 빈 공간을 완전히 채울 수 있는 조각들의 전체 칸 수를 구한다.

#### 풀이 아이디어

BFS로 테이블의 `1`이 상하좌우로 연결된 퍼즐 조각을 추출하고, 게임 보드의 `0`이 연결된 빈 공간도 같은 방법으로 추출한다.

추출한 좌표를 그대로 비교하면 모양이 같아도 격자 안의 위치가 다르기 때문에 다른 도형으로 판단된다. 따라서 모든 좌표에서 최소 행과 최소 열을 빼서 좌측 상단을 `(0, 0)`으로 맞춘다. 정규화한 좌표는 행과 열순으로 정렬한 뒤 문자열로 변환한다.

회전을 허용하기 위해 각 도형을 90도씩 세 번 회전한다. 원본을 포함한 네 방향의 문자열 표현 중 사전순으로 가장 작은 값을 해당 도형의 대표 키로 사용한다. 그러면 시작 위치나 회전 방향이 달라도 같은 모양은 같은 키를 가진다.

테이블의 퍼즐 조각은 `Map<String, Integer>`에 `대표 키 -> 조각 개수`로 저장한다. 빈 공간의 대표 키와 같은 조각이 남아 있으면 개수를 하나 감소시키고 해당 도형의 칸 수를 정답에 더한다.

#### 알고리즘 풀이

1. 테이블의 모든 칸을 순회한다.
2. 값이 `1`인 칸을 발견하면 BFS로 연결된 조각의 좌표를 모은다.
   - 큐에 넣은 칸은 즉시 `0`으로 바꾸어 다시 탐색하지 않는다.
3. 추출한 좌표의 최소 행과 최소 열을 전체 좌표에서 빼고 정렬한다.
4. 정규화된 좌표 `(r, c)`를 `(c, -r)`로 변환하여 90도 회전한다.
5. 각 회전 결과를 다시 정규화하고 정렬한 뒤 문자열 키로 변환한다.
6. 네 회전 상태의 키 중 사전순으로 가장 작은 키를 대표 키로 선택하고 해시맵에 개수를 누적한다.
7. 게임 보드의 모든 `0` 영역에도 같은 과정을 적용해 빈 공간의 대표 키를 구한다.
   - BFS로 방문한 빈칸은 `1`로 바꾼다.
8. 대표 키와 일치하는 조각이 해시맵에 남아 있으면 조각 개수를 하나 줄이고, 좌표 키에 포함된 칸 수를 정답에 더한다.

#### 시간복잡도

격자의 한 변 길이를 `N`, 하나의 도형을 구성하는 칸 수의 최댓값을 `K`라고 하자.

- 테이블과 게임 보드 BFS: 각 칸을 최대 한 번 방문하므로 `O(N²)`
- 도형 하나의 네 방향 정규화 및 정렬: `O(K log K)`
- 모든 도형을 처리하는 비용: `O(N² log K)`

따라서 전체 시간복잡도는 다음과 같다.

```text
시간복잡도: O(N² log K)
```

이 문제에서는 `K ≤ 6`으로 제한되므로 실질적으로는 `O(N²)`에 가깝다.

#### 공간복잡도

BFS 큐와 좌표 목록, 회전한 좌표 목록에 하나의 도형 크기인 `O(K)` 공간이 필요하다. 해시맵에는 서로 다른 퍼즐 모양의 키와 개수를 저장한다.

추가 저장 공간의 최대 크기를 격자 크기로 표현하면 다음과 같다.

```text
공간복잡도: O(N²)
```

별도의 `visited` 배열은 사용하지 않고, 입력 격자의 방문한 값을 반대 값으로 변경해 방문 여부를 표시한다.

#### 개선 가능한 부분

- `map.put(key, map.computeIfAbsent(key, k -> 0) + 1)`은 `map.merge(key, 1, Integer::sum)`으로 단순화할 수 있다.
- 좌표 정렬이 원본과 회전 처리 부분에 중복되어 있다. `normalize` 메서드가 이동과 정렬을 모두 담당하게 하면 중복을 줄일 수 있다.
- `countCell`이 대표 키를 `split`하여 칸 수를 다시 계산한다. 도형의 키와 칸 수를 함께 담는 객체를 반환하면 문자열 파싱을 제거할 수 있다.
- 현재 풀이는 `game_board`와 `table`을 직접 변경한다. 입력 보존이 필요한 환경이라면 별도의 `visited` 배열을 사용해야 한다.
- 제출용 코드에서는 해시맵과 매칭된 키를 출력하는 `System.out.println` 디버깅 코드를 제거할 수 있다.

#### 시행착오

- 처음에는 조각마다 네 개의 회전 좌표 목록을 모두 저장하는 `List<List<int[]>[]>` 구조를 고려했다.
  - **원인:** 빈 공간마다 모든 조각과 네 회전 상태를 직접 비교하려고 했다.
  - **해결:** 네 회전 상태 중 사전순으로 가장 작은 문자열을 대표 키로 선택하고, 같은 키의 조각 개수만 해시맵에 저장하는 방식으로 단순화했다.
  - **주의:** 회전과 이동에 관계없는 표준 형태를 만들 수 있다면 모든 상태를 각각 보관할 필요가 없다.
- BFS에서 메서드 호출마다 새 `visited` 배열을 만들었다.
  - **원인:** 하나의 연결 요소 안에서는 중복 방문을 막았지만, BFS가 끝나면 방문 정보가 사라졌다. 그 결과 바깥 반복문이 같은 조각의 다른 칸에서 조각 전체를 다시 추출했다.
  - **해결:** 큐에 추가한 즉시 테이블의 `1`은 `0`으로, 게임 보드의 `0`은 `1`로 변경해 방문 상태를 유지했다.
  - **주의:** 격자 전체를 연결 요소로 분해할 때는 탐색 호출 사이에서도 방문 정보가 유지되어야 한다.
- 초기에는 BFS로 얻은 격자의 절대 좌표를 그대로 문자열로 변환했다.
  - **원인:** 모양이 같아도 격자에서의 시작 위치가 다르면 서로 다른 키가 만들어졌다.
  - **해결:** 최소 행과 최소 열을 빼는 좌표 정규화를 적용했다.
  - **주의:** 도형을 비교할 때는 절대 위치가 아니라 좌표 간의 상대적인 관계를 비교해야 한다.
- 회전한 좌표를 정규화한 후 정렬하지 않고 바로 문자열로 변환했다.
  - **원인:** 같은 좌표 집합이어도 리스트에 나열된 순서가 다르면 다른 문자열이 만들어졌다.
  - **해결:** 원본과 모든 회전 상태에서 좌표를 행, 열순으로 정렬한 후 문자열 키를 생성했다.
  - **주의:** 집합을 순서가 있는 문자열이나 리스트로 비교할 때는 항상 일관된 정렬 기준이 필요하다.
