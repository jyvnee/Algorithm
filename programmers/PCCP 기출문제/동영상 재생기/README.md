# 동영상 재생기

## 풀이 기록

### v1

#### 문제 정의

현재 재생 위치에서 명령어를 순서대로 처리한 뒤 최종 재생 위치를 `"mm:ss"` 형식으로 반환한다.

처리해야 하는 기능은 다음과 같다.

1. `"prev"` 명령이면 현재 위치에서 10초 전으로 이동한다.
2. `"next"` 명령이면 현재 위치에서 10초 후로 이동한다.
3. 이동 전후 현재 위치가 오프닝 구간에 포함되면 오프닝 종료 시각으로 이동한다.
4. 재생 위치는 `00:00`보다 작아질 수 없고, 동영상 길이보다 커질 수 없다.

#### 풀이 아이디어

시간 문자열은 `"mm:ss"` 형식으로 고정되어 있으므로 `substring()`을 사용해 분과 초를 분리한 뒤 `int[]`로 저장했다.

```java
int[] current = {
    Integer.parseInt(pos.substring(0, 2)),
    Integer.parseInt(pos.substring(3))
};
```

각 명령어를 처리할 때는 다음 순서를 지킨다.

1. 명령 수행 전 현재 위치가 오프닝 구간인지 확인한다.
2. 오프닝 구간이면 오프닝 종료 시각으로 이동한다.
3. 명령어가 `"prev"`인지 `"next"`인지에 따라 10초 이동한다.
4. 명령 수행 후 다시 오프닝 구간인지 확인한다.
5. 모든 명령을 처리한 뒤 두 자리 형식으로 결과를 반환한다.

오프닝 구간 판별과 시간 비교를 반복해서 사용해야 하므로 `compareTime()` 메서드를 따로 두었다.

#### 알고리즘 풀이

먼저 `video_len`, `pos`, `op_start`, `op_end`를 각각 `[분, 초]` 형태의 배열로 변환한다. 이후 `commands`를 순회하면서 현재 위치를 계속 갱신한다.

오프닝 구간인지 확인할 때는 다음 조건을 사용한다.

```text
op_start <= current < op_end
```

현재 시간이 오프닝 시작 시각 이상이고, 오프닝 종료 시각보다 작으면 오프닝 안에 있다고 판단한다. 이 경우 현재 위치를 `op_end`로 변경한다.

```java
boolean afterStart = (compareStart == -1) || (compareStart == 0);
boolean beforeEnd = (compareEnd == -1);
```

`"next"` 명령은 초에 10을 더한다. 초가 60 이상이 되면 분을 1 증가시키고 초를 60으로 나눈 나머지로 보정한다. 이동한 결과가 동영상 길이보다 크면 동영상 끝 위치로 고정한다.

```java
current[1] += 10;

if (current[1] >= 60) {
    current[0] += 1;
    current[1] %= 60;
}

if (compareTime(current, videoLen) == 1) {
    current[0] = videoLen[0];
    current[1] = videoLen[1];
}
```

`"prev"` 명령은 초에서 10을 뺀다. 초가 음수가 되면 1분을 빌려와 초를 보정한다. 이후 이동한 결과가 `00:00`보다 작으면 처음 위치로 고정한다.

```java
current[1] -= 10;

if (current[1] < 0) {
    current[1] = (current[1] + 60) % 60;
    current[0] -= 1;
}

if (compareTime(new int[]{0, 0}, current) == 1) {
    current[0] = 0;
    current[1] = 0;
}
```

최종 결과는 `String.format("%02d:%02d", current[0], current[1])`을 사용해 항상 두 자리 형식으로 반환한다.

#### 시간복잡도

**O(C)**

`commands`의 길이를 `C`라고 하면, 각 명령마다 오프닝 구간 확인과 10초 이동을 상수 시간에 수행한다.

```text
O(C)
```

문제에서 `commands`의 최대 길이는 100이므로 충분히 효율적이다.

#### 공간복잡도

**O(1)**

입력 배열을 제외하면 시간 정보를 저장하는 몇 개의 `int[]`와 변수만 사용한다. 명령 개수와 관계없이 추가 메모리 사용량은 일정하다.

#### 개선 가능한 부분

- 시간 정보를 `[분, 초]` 배열로 관리하면 비교와 보정 로직이 길어진다. 모든 시간을 초 단위 정수로 변환하면 구현을 더 단순하게 만들 수 있다.

  ```java
  int time = minute * 60 + second;
  ```

- 오프닝 구간 판별도 초 단위로 변환하면 `opStart <= current && current <= opEnd`처럼 더 직관적으로 표현할 수 있다.
- `moveNext`, `movePrev`는 실제 명령어 의미와 맞게 유지해야 한다. 이름과 동작이 반대로 연결되면 테스트에서 바로 틀릴 수 있다.

#### 시행착오

- **문제:** 반환값이 `"0:5"`처럼 두 자리 형식을 지키지 않을 수 있었다.
- **원인:** `current[0] + ":" + current[1]`로 문자열을 직접 이어 붙이면 한 자리 수에 앞자리 `0`이 붙지 않는다.
- **해결:** `String.format("%02d:%02d", current[0], current[1])`로 `"mm:ss"` 형식을 맞췄다.

- **문제:** 초에서 10을 뺐을 때 음수가 되는 경우 보정이 필요했다.
- **원인:** Java의 `%` 연산은 수학적 modulo가 아니라 remainder라서 왼쪽 피연산자가 음수이면 결과도 음수가 될 수 있다. 예를 들어 `-5 % 60`은 `-5`이다.
- **해결:** 초가 음수일 때 `(current[1] + 60) % 60`으로 양수 범위의 초로 보정하고, 분을 1 감소시켰다.

- **참고:** `"mm:ss"`처럼 구분자가 있는 문자열은 `split(":")`으로 나누는 방법도 가능하다. 다만 이 문제처럼 길이가 항상 5로 고정되어 있으면 `substring(0, 2)`, `substring(3)`을 사용해도 충분하다.
