# 주차 요금 계산

## 알고리즘 분류

- 구현
- 문자열 처리
- 정렬된 맵 (`TreeMap`)

## 문제 정의

차량별 입·출차 기록을 바탕으로 누적 주차 시간을 계산하고, 요금표에 따라 주차 요금을 구한다. 출차 기록이 없는 차량은 23:59에 출차한 것으로 간주하며, 결과는 차량 번호의 오름차순으로 반환해야 한다.

## 풀이 기록

### v1

#### 풀이 아이디어

차량별로 `[누적 주차 시간, 최근 입차 시각]`을 저장한다. 입차 시각이 `-1`이면 현재 주차장 밖에 있다는 의미다.

차량 번호를 오름차순으로 반환해야 하므로 `TreeMap<String, int[]>`을 사용했다. 이를 통해 별도의 차량 번호 정렬 과정 없이 키를 순회하며 결과를 생성할 수 있다.

#### 알고리즘 풀이

1. 각 기록을 공백으로 나누어 시각, 차량 번호, 입·출차 여부를 얻는다.
2. 처음 등장한 차량이면 누적 주차 시간을 `0`, 입차 시각을 현재 시각으로 저장한다.
3. 이미 등장한 차량의 `IN` 기록이면 최근 입차 시각을 갱신한다.
4. `OUT` 기록이면 최근 입차 시각부터 현재 시각까지의 분 차이를 누적한 뒤, 입차 시각을 `-1`로 변경한다.
5. 모든 기록을 처리한 후 입차 시각이 `-1`이 아닌 차량은 23:59에 출차한 것으로 간주하여 주차 시간을 추가한다.
6. `TreeMap`의 키를 순회하며 누적 시간에 따른 요금을 계산해 결과 배열에 담는다.

시각은 `HH:MM`의 콜론을 제거한 `HHMM` 형태의 정수로 변환한다. 두 시각의 차이는 각각 시와 분으로 분리한 뒤 다음과 같이 분 단위로 계산한다.

```text
(출차 시 - 입차 시) × 60 + (출차 분 - 입차 분)
```

누적 주차 시간이 기본 시간을 초과하면 초과 시간을 단위 시간으로 나눈 값을 올림하여 추가 요금을 계산한다.

#### 시간복잡도

`R`을 입·출차 기록 수, `C`를 서로 다른 차량 수라고 하자.

- 각 기록에서 `TreeMap`을 조회하거나 추가하는 데 `O(log C)`가 필요하므로 기록 처리는 `O(R log C)`이다.
- 차량별 요금을 계산할 때 모든 키를 순회하며 `get`을 호출하므로 `O(C log C)`이다.

따라서 전체 시간복잡도는 다음과 같다.

```text
O(R log C + C log C)
→ O(R log C)  (C ≤ R)
```

#### 공간복잡도

`TreeMap`에 차량별 누적 시간과 입차 시각을 저장하므로 `O(C)`이다. 반환할 결과 배열도 `O(C)`의 공간을 사용한다.

#### 개선 가능한 부분

- 요금의 올림 계산은 실수 연산 대신 `(초과 시간 + 단위 시간 - 1) / 단위 시간`의 정수 연산으로 구하면 정밀도를 고려할 필요가 없고 의도도 더 명확해진다.
- `keySet()`을 순회하며 다시 `get()`을 호출하기보다 `entrySet()`을 순회하면 요금 계산 단계를 `O(C)`로 줄일 수 있다.
- `int[]`의 각 인덱스가 무엇을 의미하는지 코드만으로는 알기 어렵다. 누적 시간과 입차 시각을 필드로 가지는 클래스를 두면 가독성을 높일 수 있다.
- 미출차 차량의 시간을 처리한 후 `value[1] = 0`으로 변경하는 코드는 이후에 상태를 다시 사용하지 않으므로 제거할 수 있다.

#### 시행착오

- **원인**: `OUT` 기록을 처리한 후 최근 입차 시각을 `0`으로 초기화했다. 그러나 `00:00`을 정수로 변환한 값도 `0`이므로, `0`은 주차장 밖에 있는 상태와 00:00에 입차한 상태를 구분하지 못한다.
- **해결 방법**: 유효한 시각 범위에 포함되지 않는 `-1`을 출차 상태의 표식값으로 사용했다. 이제 `value[1] != -1`이면 미출차 차량임을 명확히 판별할 수 있다.
- **이후 주의할 점**: 특정 값을 상태 표식으로 사용할 때는 그 값이 실제 입력과 충돌하지 않는지 먼저 확인해야 한다.
