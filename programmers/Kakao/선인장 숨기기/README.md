# 선인장 숨기기

## 알고리즘 분류

Union-Find(분리집합), 오프라인 2차원 구간 처리(구간 스킵 기법)

## 문제 정의

- m×n 격자에 h×w 크기의 사각형(선인장 구역)을 놓을 좌상단 좌표를 정한다.
- drops에 주어진 순서대로 빗방울이 격자 칸에 떨어지며, 각 사각형 후보 위치가 "처음으로 비를 맞는 시점"(drops의 인덱스)을 알아야 한다.
- 우선순위
  1. 끝까지 비를 맞지 않는 위치가 있다면 그 중에서 선택
  2. 없다면 가장 늦게 비를 맞는 위치
  3. 동률이면 가장 위쪽 행, 그래도 동률이면 가장 왼쪽 열

## 풀이 기록

### v1

#### 풀이 아이디어

- 선인장 구역의 좌상단 (r, c)는 r ∈ [0, m-h], c ∈ [0, n-w] 범위의 "후보 격자"를 이룬다. R = m-h+1, C = n-w+1이라 하자.
- 빗방울 pos = (y, x)가 후보 (r, c)의 사각형에 포함되려면 r ≤ y ≤ r+h-1, c ≤ x ≤ c+w-1 이어야 하므로, pos 하나가 처음 침수시키는 후보 좌표 범위는
  - r ∈ [max(y-h+1, 0), min(y, m-h)]
  - c ∈ [max(x-w+1, 0), min(x, n-w)]
  인 직사각형이다.
- drops를 순서대로 처리하면서 이 직사각형 범위를 매번 전부 순회하되, 이미 침수된 칸은 `continue`로 건너뛰고 아직 침수되지 않은 칸만 침수 처리한다.
- 이 drop에서 새로 침수된 칸 중 가장 먼저(행→열 오름차순) 마킹된 칸을 `firstR/firstC`로 기억해둔다. 만약 이 drop 처리로 `remaining`이 0이 되면(모든 후보가 침수됨) `firstR/firstC`가 곧 "동시에 마지막으로 침수된 후보들 중 가장 위쪽·왼쪽" 좌표이므로 그대로 반환한다.
- drops를 모두 처리했는데도 침수되지 않은 후보가 남아있다면, 그중 가장 위쪽 행·왼쪽 열인 좌표를 반환한다.

#### 알고리즘 풀이

1. R = m-h+1, C = n-w+1로 후보 격자의 크기를 구하고, `remaining = R*C`로 시작한다.
2. drops를 순서대로 순회하며 각 pos에 대해 침수 범위 `[startRow,endRow] × [startCol,endCol]`을 계산한다.
3. 이 범위를 행→열 순서로 전부 순회하며, 이미 침수된 칸은 건너뛰고 미침수 칸만 침수 처리(`visited[r][c]=true`, `remaining--`)한다.
4. 이 drop에서 새로 침수된 첫 칸을 `firstR/firstC`에 기억해둔다.
5. 순회가 끝난 뒤 `remaining == 0`이면 `(firstR, firstC)`를 즉시 반환한다.
6. drops를 모두 처리했는데도 `remaining > 0`이면, 침수되지 않은 후보 중 행→열 오름차순으로 처음 만나는 좌표를 반환한다.

#### 시간복잡도

R = m-h+1, C = n-w+1, D = drops.length, 한 drop의 침수 범위 크기를 각각 `min(h,R)`, `min(w,C)`라 하면

```
시간복잡도: O(D × min(h,R) × min(w,C))  (최악의 경우 O(D × h × w)에 근접)
```

drop마다 이미 침수된 칸까지 포함해 범위 전체를 매번 처음부터 다시 순회하기 때문에, 겹치는 drop이 많으면 같은 칸을 반복해서 재확인하는 비용이 계속 누적된다.

#### 공간복잡도

```
공간복잡도: O(R × C)
```

- `visited`: O(R×C)

#### 개선 가능한 부분

- 이미 침수된 칸/행 구간을 매번 한 칸씩 다시 확인하는 구조가 성능의 병목이다. "다음 미침수 위치를 즉시 찾아주는" 자료구조(Union-Find)를 도입하면 이미 처리된 구간을 상각 O(α) 시간에 건너뛸 수 있다 → v2에서 개선.

#### 시행착오

- **범위 계산 실수**: 후보 (r,c)가 빗방울 pos를 포함하는 조건에서 `endRow`를 `pos[0] + h - 1`로 계산했다. `startRow`는 `pos[0] - h + 1`로 올바르게 뺐지만, `endRow`에도 실수로 `+h-1`을 더해 범위를 `h-1`칸만큼 과도하게 넓게 잡는 바람에 실제로는 안전한 후보까지 침수된 것으로 잘못 마킹됐다.
  - 원인: r의 상한은 `pos[0]`이어야 하는데(윈도우가 pos를 덮으려면 `r ≤ pos[0]`), 시작점 계산에서 쓴 `h-1` 보정을 끝점에도 습관적으로 적용했다.
  - 해결: `endRow = min(pos[0], m-h)`, `endCol = min(pos[1], n-w)`로 수정.
  - 주의할 점: 구간의 시작/끝을 부등식에서 각각 독립적으로 유도해야지, 한쪽 식에서 쓴 보정 항을 다른 쪽에 그대로 재사용하면 안 된다.
- **동점 처리 실수**: 범위를 고친 뒤에도, 하나의 drop이 여러 후보를 동시에 처음 침수시키며 `remaining`을 한 번에 0으로 만드는 경우(예: h, w가 커서 한 drop이 후보 전체를 덮는 경우) 오답이 나왔다.
  - 원인: 최초 코드는 `remaining == 1`이 되는 순간 그 시점에 순회 중이던 칸(범위의 오른쪽 아래에 가까운 칸)을 그대로 반환했는데, 동시에 침수되는 후보들은 전부 첫 침수 시각이 같은 "동률"이므로 그중 가장 위쪽·왼쪽 후보를 반환해야 했다.
  - 해결: drop 처리 시작 시 `firstR/firstC`를 초기화해두고, 이 drop에서 새로 마킹되는 첫 칸(행→열 오름차순 순회상 최초)을 기억했다가 `remaining == 0`이 됐을 때 그 칸을 반환하도록 수정.
  - 주의할 점: 여러 항목이 한 번에 갱신되는 배치 처리에서는, 처리 순회 순서(raster order)가 문제의 우선순위 기준과 실제로 일치하는지 반드시 검증해야 한다.
- **시간초과**: 위 두 버그를 고쳐 정답은 맞지만, drop마다 침수 범위를 처음부터 끝까지 순회하며 이미 침수된 칸을 하나씩 `continue`로 건너뛰는 방식이라 drop 수와 h×w가 모두 클 경우 시간초과가 발생했다. → v2에서 Union-Find로 해결.

### v2

#### 풀이 아이디어

- v1의 정답 로직(순서대로 drop을 처리하며 침수시키고, 한 drop이 remaining을 0으로 만들면 그 drop이 새로 침수시킨 칸 중 가장 위쪽·왼쪽을 반환)은 그대로 유지한다.
- 병목이었던 "이미 침수된 칸/행을 매번 한 칸씩 재확인"하는 부분만, "다음 미침수 위치를 즉시 찾아주는" Union-Find로 교체한다.
- 열 방향 Union-Find를 행마다 하나씩 두어 한 행 안에서 다음 미침수 열을 즉시 찾고, 행 방향 Union-Find를 하나 더 두어 완전히 침수된 행 자체를 건너뛴다. 두 단계를 겹쳐 쓰면 이미 처리된 열 구간과 행 구간을 모두 상각 O(α) 시간에 건너뛸 수 있다.

#### 알고리즘 풀이

1. R = m-h+1, C = n-w+1로 후보 격자의 크기를 구한다.
2. 행마다 독립된 열 Union-Find `colParent`를 준비한다. 행 r의 열 c는 초기에 자기 자신(c)을 가리키고, C는 "이 행에 더 이상 미침수 칸이 없음"을 뜻하는 보초(sentinel) 값으로 쓴다.
3. 행 Union-Find `rowParent`를 준비한다. 초기에는 각 행이 자기 자신을 가리킨다.
4. `remaining = R * C`(아직 침수되지 않은 후보 수)로 시작한다.
5. drops를 순서대로 순회하며 각 pos에 대해 침수 범위 `[startRow,endRow] × [startCol,endCol]`을 계산한다.
6. `findRow`로 startRow 이상인 첫 미완료 행을 찾고, 그 행 안에서 `findCol`로 startCol 이상인 첫 미침수 열을 찾아 순서대로 침수 처리한다. 칸을 침수 처리할 때마다 `colParent[c] = c + 1`로 합쳐 이후 탐색이 그 칸을 건너뛰게 만든다.
   - 한 행의 처리가 끝나면, 그 행의 모든 열(0~C-1)이 침수됐는지(`findCol(r, 0) == C`) 확인하고, 그렇다면 `rowParent[r] = r + 1`로 합쳐 해당 행 자체를 다음부터 건너뛰게 만든다.
7. 이 drop이 새로 침수시킨 후보 중 가장 먼저 마킹된 좌표를 `(firstR, firstC)`로 기억한다. 순회 순서가 행→열 오름차순이므로 자연스럽게 그 그룹에서 가장 위쪽·왼쪽 좌표가 된다.
8. `remaining`이 0이 되면(이 drop으로 모든 후보가 침수됨) `(firstR, firstC)`를 즉시 반환한다.
9. drops를 모두 처리했는데도 remaining > 0이면, 침수되지 않은 후보 중 행→열 오름차순으로 처음 만나는 좌표를 반환한다.

#### 시간복잡도

R = m-h+1, C = n-w+1, D = drops.length 라 하면

```
시간복잡도: O((R × C + D) × α(R × C)) ≈ O(R × C + D)
```

- 각 후보 칸은 평생 정확히 한 번만 새로 침수 처리되므로 총 마킹 비용은 O(R×C)
- 이미 처리된 열/행 구간은 Union-Find의 경로 압축(path halving)으로 상각 O(α)에 건너뜀
- 각 drop이 시작/종료 지점을 찾기 위한 `find` 호출 비용도 O(α) 수준

#### 공간복잡도

```
공간복잡도: O(R × C)
```

- `visited`: O(R×C)
- `colParent`: O(R×(C+1)) = O(R×C + R)
- `rowParent`: O(R+1)

#### 개선 가능한 부분

- `colParent`의 각 행에서 `c == C` 여부만으로 "그 칸/행이 완전히 침수됐는지" 판별할 수 있으므로, 별도의 `visited` 배열 없이 `colParent`/`rowParent`만으로 상태를 표현하면 메모리를 더 줄일 수 있다.
- `firstR`/`firstC`를 `-1`로 초기화해 "아직 마킹 안 함"을 표시하는 대신, 더 간결한 방식으로 표현할 여지가 있다(가독성 vs 코드 길이의 트레이드오프 수준이라 현재 방식도 충분히 명확함).

#### 버전별 비교 (v1 → v2)

- "이미 침수된 칸/행을 매번 한 칸씩 재확인"하던 이중 for + `continue` 구조를, 행마다 하나씩 둔 열 Union-Find(`findCol`)와 전체 행 Union-Find(`findRow`)로 대체했다.
- 정답을 계산하는 핵심 로직(순서대로 drop 처리, `remaining==0` 시 `firstR/firstC` 반환, 마지막에 미침수 후보 스캔)은 v1과 동일하게 유지된다 — 바뀐 것은 "침수 표시 및 다음 미침수 위치 탐색"을 구현하는 자료구조뿐이다.
- 시간복잡도가 O(D × h × w)에 근접하던 v1에서 O(R×C + D)로 개선되어 시간초과가 해결됐다.
- 대신 행마다 별도의 Union-Find 배열(`colParent`)을 유지해야 하므로 공간복잡도가 O(R×C)에서 상수 배 더 늘었다(여전히 O(R×C)이지만 실질 메모리 사용량은 증가).

#### 시행착오

- **시간초과**: v1은 두 버그를 모두 고쳐 정답은 맞았지만, drop마다 침수 범위를 처음부터 끝까지 순회하며 이미 침수된 칸을 하나씩 `continue`로 건너뛰는 방식이라, drop 수와 h×w가 모두 클 경우 최악의 경우 O(drops × h × w)까지 커져 시간초과가 발생했다.
  - 원인: 이미 침수된 칸/행을 매번 한 칸씩 다시 확인하는 구조라, 겹치는 drop이 많을수록 낭비되는 재확인 비용이 누적됐다.
  - 해결: 이미 침수된 열 구간은 `findCol`, 이미 완전히 침수된 행은 `findRow`가 경로 압축으로 즉시 건너뛰도록 Union-Find 두 겹을 도입해, 각 칸이 평생 한 번만 처리되는 구조로 변경.
  - 주의할 점: "구간을 반복적으로 갱신하고, 이미 처리된 부분은 다시 볼 필요 없는" 유형의 문제에서는 `continue` 기반 순회보다 Union-Find의 "다음 미방문 위치 찾기" 패턴이 훨씬 효율적이라는 점을 앞으로도 우선 고려할 것.
