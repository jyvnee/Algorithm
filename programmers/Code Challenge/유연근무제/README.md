# 유연근무제

## 알고리즘 분류

- 구현
- 시간 계산
- 나머지 연산

## 풀이 기록

### v1

#### 문제 정의

각 직원이 설정한 출근 희망 시각에 10분을 더한 시각을 지각 기준으로 삼는다. 이벤트가 진행되는 7일 중 토요일과 일요일을 제외한 모든 날에 기준 시각 이내로 출근한 직원의 수를 구한다.

#### 풀이 아이디어

각 직원에 대해 다음 과정을 수행한다.

1. 출근 희망 시각에 10분을 더해 허용되는 마지막 출근 시각을 구한다.
2. 10분을 더한 결과의 분이 60 이상이면 시간을 1 증가시키고 분을 보정한다.
3. 7일간의 출근 기록을 순회하며 나머지 연산으로 실제 요일을 계산한다.
4. 주말 기록은 무시하고, 평일에 한 번이라도 기준 시각보다 늦은 기록이 있으면 상품을 받을 수 없다고 판단한다.

#### 알고리즘 풀이

시각은 `시 × 100 + 분` 형식이므로 단순히 10을 더했을 때 분이 60을 넘을 수 있다. 예를 들어 `958 + 10 = 968`은 올바른 시각 표현이 아니므로 `1008`로 보정한다.

```java
int time = schedule + 10;

if (time % 100 >= 60) {
    int hour = time / 100 + 1;
    int minute = time % 100 % 60;
    time = hour * 100 + minute;
}
```

이벤트 시작 요일은 1부터 7까지이지만, 나머지 연산은 0부터 6까지의 값을 만든다. 따라서 시작 요일에서 1을 빼 0 기준으로 변환한 뒤, `i`일을 더하고 나머지 연산을 적용한다. 마지막에 1을 더해 다시 1부터 7까지의 요일 표현으로 복원한다.

```java
int day = (startday - 1 + i) % 7 + 1;
```

이 계산으로 일요일에 시작하더라도 `7, 1, 2, 3, 4, 5, 6`처럼 요일이 정상적으로 순환한다. `day`가 6 또는 7이면 주말이므로 해당 기록을 검사하지 않는다.

평일 출근 시각이 허용 시각보다 늦으면 즉시 `false`를 반환한다. 7일을 모두 확인할 때까지 지각이 없었다면 `true`를 반환한다.

#### 시간복잡도

**O(N)**

직원 `N`명에 대해 각각 7일의 기록을 확인한다.

```text
O(N × 7)
→ O(N)
```

7은 고정된 상수이므로 전체 시간복잡도는 `O(N)`이다.

#### 공간복잡도

**O(1)**

입력 배열 외에 직원 수와 관계없이 일정한 개수의 변수만 사용한다.

#### 개선 가능한 부분

- 시각을 처음부터 분 단위로 변환하면 60분 진법 보정 로직을 더 직관적으로 표현할 수 있다.

  ```java
  int limit = (schedule / 100) * 60 + schedule % 100 + 10;
  int arrival = (timelog / 100) * 60 + timelog % 100;
  ```

- `time`을 `limitTime`, `day`를 `currentDay`처럼 의미가 더 명확한 이름으로 바꾸면 가독성이 좋아진다.
- 현재 풀이는 각 직원의 평일 기록을 한 번씩만 확인하므로 점근적 시간복잡도 `O(N)`보다 더 개선하기 어렵다.

#### 시행착오

- **문제:** 초기 구현에서 `startday + i`가 6 또는 7인지만 확인했다.
- **원인:** `startday + i`가 7을 넘을 때 다음 주의 요일로 순환되지 않았다. 예를 들어 일요일에 시작하면 7일차 토요일이 `13`으로 계산되어 평일처럼 검사되었다.
- **해결:** `(startday - 1 + i) % 7 + 1`로 요일을 항상 1부터 7 사이의 값으로 정규화했다.
- **주의할 점:** 요일처럼 일정한 범위가 반복되는 값은 경계를 넘는 입력을 반드시 확인하고, 나머지 연산으로 정규화한다.
