# 1204. 최빈수 구하기

## 알고리즘 분류

카운팅 (Counting) / 배열

## 문제 정의

학생 1000명의 점수(0~100점) 중 가장 많이 나온 값(최빈수)을 구한다. 최빈수가 여러 개면 그중 가장 큰 점수를 출력한다.

## 풀이 기록

### v1

#### 풀이 아이디어

점수의 범위가 0~100으로 제한되어 있으므로, 크기 101짜리 배열 `count`에 각 점수의 등장 횟수를 세어 저장한다. 이후 배열을 0번부터 100번까지 순회하면서 최댓값을 갱신하되, 동점(`count[i] >= maxCount`)일 때도 갱신하도록 하여 자연스럽게 더 큰 점수가 최종 answer로 남도록 한다.

#### 알고리즘 풀이

1. 점수(0~100)를 인덱스로 사용하는 `count` 배열을 크기 101로 선언한다.
2. 한 줄에 주어지는 1000개의 점수를 `StringTokenizer`로 토큰화하며 `count[score]++`로 누적한다.
3. `i = 0..100`을 순회하며 `count[i] >= maxCount`이면 `maxCount`, `answer`를 갱신한다.
   - 비교 연산자를 `>`가 아닌 `>=`로 두었기 때문에, 카운트가 같은 값이 나중에(더 큰 인덱스에서) 발견되면 항상 `answer`가 갱신된다. 배열을 인덱스 오름차순으로 순회하므로 결과적으로 "카운트가 같다면 더 큰 점수"가 남는다.
4. 테스트 케이스별로 `#test_case answer` 형태로 `StringBuilder`에 append 후 한 번에 출력한다.

#### 시간복잡도

O(T × 1000)

테스트 케이스마다 점수 1000개를 순회하며 카운팅(O(1000))하고, 이후 0~100 구간을 순회(O(101))하므로 케이스당 O(1000 + 101) → T개 케이스에 대해 O(T × 1000).

#### 공간복잡도

O(1) (테스트 케이스당 고정 크기 101 배열만 사용, 입력 크기와 무관)

출력을 모아두는 `StringBuilder`까지 고려하면 O(T)이지만, 문제 풀이에 필요한 보조 공간 자체는 상수 크기다.

#### 개선 가능한 부분

- 현재는 `BufferedReader` + `StringTokenizer` 조합으로 충분히 빠르며, 별도의 개선 여지는 크지 않다.
- `count[i] >= maxCount` 조건에 의존해 "동점 시 큰 값 우선"을 구현하는 방식은 다소 암묵적이다. 의도를 명확히 하려면 `count[i] > maxCount`로 최댓값만 갱신하고, 동점 시에는 별도로 `Math.max(answer, i)`를 적용하는 방식으로 바꿔 가독성을 높일 수 있다.

#### 시행착오

- **입력을 한 줄 덜 읽는 문제**: 각 테스트 케이스는 "테스트 케이스 번호" 줄과 "점수 1000개" 줄, 총 두 줄로 구성되는데, 처음에는 번호 줄을 건너뛰지 않고 바로 `br.readLine()`으로 점수를 읽으려 했다. 그 결과 점수 대신 번호 한 줄(예: `"1"`)만 토큰화되어 `st.nextToken()`을 반복 호출하는 중 `NoSuchElementException`이 발생했다.
  - 원인: 입력 형식(번호 줄 + 점수 줄)을 고려하지 않고 점수 줄만 있다고 가정함.
  - 해결: 점수를 읽기 전에 `br.readLine()`을 한 번 더 호출해 번호 줄을 소비하도록 수정.
  - 주의할 점: 멀티 테스트 케이스 입력에서 각 케이스가 몇 줄로 구성되는지 반드시 확인하고 그만큼 `readLine()`을 호출해야 한다.
